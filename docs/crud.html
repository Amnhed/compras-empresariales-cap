before corre antes de tocar la base y puede rechazar la petición. after corre cuando la fila ya se leyó y puede completar la respuesta. on reemplaza la operación; en el CRUD de este proyecto no hace falta, porque el genérico de CAP basta.

Crear, al guardar el borrador

Exige al menos un artículo, cantidad y precio mayores a cero. Si el total pasa de 15000, el estado queda Retenida - Requiere Revisión. Si no, Aprobada Automáticamente. El cliente no envía el estado final.

this.before('CREATE', OrdenesCompra, async (req) => {
    const orden = req.data;
    const posiciones = await posicionesDe(orden, Posiciones);
    if (posiciones.length === 0) {
        return req.reject(400, 'Una orden debe tener artículos.');
    }
    // ... suma cantidad * precio ...
    orden.estado = totalAcumulado > UMBRAL ? RETENIDA : APROBADA_AUTO;
});

Leer

importeTotal se calcula en after READ. El borrador es la entidad OrdenesCompra.drafts, así que el mismo cálculo está registrado también ahí. Si la petición no trajo $expand=posiciones, el handler lee la tabla activa o la de borrador.

Editar y borrar

Solo si el estado guardado es Pendiente o Retenida - Requiere Revisión. Una orden aprobada o rechazada responde 409. Se lee el estado de la base porque req.data en un PATCH puede traer únicamente el folio nuevo.

this.before('UPDATE', OrdenesCompra, async (req) => {
    await exigirEditable(req, OrdenesCompra, 'editar');
});
this.before('DELETE', OrdenesCompra, async (req) => {
    await exigirEditable(req, OrdenesCompra, 'borrar');
});
