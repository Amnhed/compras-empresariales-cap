Servicio y OData

La proyección es el contrato. OData V4 es cómo viaja por HTTP.

Arquitectura Modelo CDS Servicio OData CRUD Acciones Seguridad

sap.compras.OrdenesCompra es la tabla. ComprasService.OrdenesCompra es lo que el cliente ve. La proyección copia la entidad al servicio. CAP publica ese servicio en /odata/v4/compras sin que escribas un controlador por cada URL.

@odata.draft.enabled añade el borrador. Crear en Fiori no inserta la orden definitiva: abre un borrador y Guardar lo activa.

service ComprasService @(requires: 'authenticated-user') {
    @odata.draft.enabled
    entity OrdenesCompra as projection on db.OrdenesCompra actions {
        action aprobar();
        action rechazar();
    };
    entity Posiciones as projection on db.Posiciones;
}

GET /odata/v4/compras/$metadata describe entidades, claves, acciones y anotaciones de UI. Fiori arma la lista con eso.

OperaciónHTTPQué pasa
Abrir registroPOST /OrdenesCompraCrea el borrador. No valida todavía.
GuardarPOST .../draftActivateCorre before CREATE y persiste cabecera y artículos.
LeerGET /OrdenesCompraLista las activas. $expand=posiciones trae los artículos en la misma respuesta.
Filtrar$filter=estado eq 'Aprobada'OData traduce el filtro a la consulta.
EditarPATCH /OrdenesCompra(ID=...,IsActiveEntity=true)Corre before UPDATE.
BorrarDELETE sobre la misma claveCorre before DELETE. La composición borra las posiciones.

Con borrador la clave tiene dos partes: el UUID y IsActiveEntity. false es el borrador; true es la orden guardada. Las peticiones de ejemplo están en test.http.
